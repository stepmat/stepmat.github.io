The Problem: Travelling Salesman

The Travelling Salesman Problem (TSP) asks: given a set of cities and the distances between them, what is the shortest possible route that visits every city exactly once and returns to the starting city? It's a classic NP-hard problem — as the number of cities grows, the number of possible routes explodes factorially, so checking every possibility quickly becomes impossible. Instead, we need algorithms that find very good (though not necessarily perfect) solutions in a reasonable amount of time. Ant Colony Optimization is one such approach.

The Algorithm: Ant Colony Optimization

Ant Colony Optimization (ACO) doesn't refer to one specific algorithm, but to a family of algorithms inspired by how real ants find short paths between their colony and food. As ants move, they lay down a chemical called pheromone, and tend to prefer paths that already have more of it. Because shorter paths get walked (and re-walked) faster than longer ones, pheromone builds up on them more quickly — while pheromone on every path also slowly evaporates over time. This creates a feedback loop: good, short paths get reinforced, and poor, long paths fade away.

This simulation implements Ant System, the original ACO algorithm proposed by Marco Dorigo in 1991, applied to the TSP. Artificial ants differ from real ones in that they have memory (they remember which cities they've already visited), they aren't blind (they can sense the distance to each city), and they operate in discrete time steps — one city visited per step. Each full pass, where every ant builds a complete tour, is one iteration.

How one iteration works

  1. Every ant is placed on a random starting city.
  2. Each ant repeatedly picks the next unvisited city to move to. The probability of picking a particular city is higher when there is more pheromone on that edge, and higher when the city is closer — balanced by the alpha and beta parameters described below.
  3. Once every ant has visited all cities (and implicitly returns to its starting city), the length of each ant's tour is calculated.
  4. The shortest tour found this iteration is compared against the best tour found so far.
  5. Pheromone on every edge evaporates a little, then each ant deposits fresh pheromone along the edges of the tour it just walked — shorter tours deposit proportionally more pheromone per edge.
  6. The ants' tours are cleared and the process repeats for the next iteration.

Over many iterations, pheromone accumulates on the edges that tend to appear in short tours, steering later ants towards increasingly better routes.

The pheromone update formula

For each edge between city i and city j, the pheromone level after evaporation and deposit is:

τij(new) = ρ · τij(old) + Δτij
Δτij = sum over all ants of (Q / Lk), for every ant k whose tour used edge ij

where ρ is the evaporation rate, Q is the pheromone deposit constant, and Lk is the total length of ant k's tour.

The city-selection formula

When an ant standing at city i chooses its next city j from the remaining unvisited cities, the probability of choosing j is:

pij = ( τijα · ηijβ )  /  Σk∈unvisited ( τikα · ηikβ )

where ηij = 1 / dij (the inverse of the distance between cities i and j), α controls how much weight is given to pheromone, and β controls how much weight is given to proximity.

Meaning of each variable / control

ControlSymbolMeaning
# of citiesn How many cities to randomly place on the canvas when you click Generate. This defines the size of the TSP instance to solve.
Evaporationρ (rho) The fraction of pheromone that remains on each edge after every iteration (e.g. 0.7 means 30% evaporates each iteration). Lower values make old trails disappear faster, encouraging more exploration; higher values make the colony converge on a route more quickly but risk settling on a mediocre one.
QQ A constant controlling how much pheromone each ant deposits on the edges of its tour. The amount added to each edge of an ant's tour is Q divided by that ant's total tour length, so shorter tours always deposit more pheromone.
Alphaα (alpha) How strongly existing pheromone levels influence an ant's choice of next city. α = 0 would make ants ignore pheromone entirely and rely only on distance.
Betaβ (beta) How strongly the distance to a candidate city influences an ant's choice (nearby cities are preferred). β = 0 would make ants ignore distance and rely only on pheromone.
% of antsm / n The number of ants used, expressed as a percentage of the number of cities. More ants explore more of the search space per iteration but cost more to simulate.
Iterations— How many full rounds of "all ants build a tour, then pheromone is updated" the simulation will run before stopping automatically.
